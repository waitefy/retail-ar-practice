# Демонстрационный каталог

Данные: [catalog.json](../src/data/catalog.json).
Входы, результаты и условия отказа функций:
[контракты операций](operation-contracts.md).

Каталог описывает один вымышленный товар — помаду «Мягкий цвет» — и три
варианта для обычного просмотра, сравнения оттенков и предварительного выбора.
RGB заданы для учебного приближённого наложения, а не для точного воспроизведения
цвета реального косметического продукта.

## Записи каталога

| Вариант | Артикул | Оттенок | Масса нетто, г | Материалы в порядке показа |
|---|---|---|---|---|
| V001 | DEMO-001 | S001 — Розовый, RGB (190, 90, 120) | 3,5 | M002 — упаковка; M001 — общая палитра |
| V002 | DEMO-002 | S002 — Ягодный, RGB (135, 45, 85) | 3,5 | M002 — упаковка; M001 — общая палитра |
| V003 | DEMO-003 | S001 — Розовый, RGB (190, 90, 120) | 1,5 | M003 — мини-упаковка; M001 — общая палитра |

Ссылки на домене `retail-ar.example` — учебные обозначения страницы товара и
трёх материалов. Файлы изображений в этот пример не входят; программа
может выдавать метаданные и ссылки, не загружая их по сети. Наличие ссылки
само по себе не подтверждает доступность материала. Возможность наложения
проверяется отдельно по параметрам оттенка, изображению и контуру.

## Пять сущностей и ключи

| Коллекция JSON | Сущность | Первичный ключ | Внешние ключи |
|---|---|---|---|
| products | Товар | product_id | — |
| variants | Вариант товара | variant_id | product_id → products; shade_id → shades |
| shades | Оттенок | shade_id | — |
| materials | Материал каталога | material_id | — |
| variant_materials | Материал варианта | (variant_id, material_id) | variant_id → variants; material_id → materials |

Всего: 1 товар, 3 варианта, 2 оттенка, 3 материала, 6 записей связи.
Каждый вариант принадлежит ровно одному товару и использует ровно один оттенок.
Каждая запись связи соединяет ровно один вариант с ровно одним материалом.

Название и описание товара хранятся в `products`, а не повторяются в вариантах.
Название и RGB оттенка хранятся в `shades`: V001 и V003 используют один S001,
хотя отличаются артикулом и массой. Название и адрес материала хранятся в
`materials`, а назначение и порядок показа — в связи `variant_materials`.
Читаемое обозначение варианта собирается из связанных записей при выводе.

### Обоснование M:N

У каждого варианта два материала. Общая палитра M001 относится к трём
вариантам; фотография полноразмерной упаковки M002 — к двум. Следовательно,
вариант может использовать несколько материалов, а материал — несколько
вариантов. Для получения материалов V001 программа выбирает две записи
`variant_materials` и по их ключам получает M002 и M001 из `materials`.

Ассоциативная сущность нужна для выдачи карточки варианта. Общий материал
не копируется: изменение его адреса требует одной правки в `materials`.
Материал M002 показывает общую упаковку без обозначения оттенка, поэтому его
совместное использование V001 и V002 не подменяет фотографию конкретного цвета.

### Основания нормализации

- **1НФ:** каждое поле записи содержит одно значение; компоненты RGB
  представлены отдельными атрибутами. Набор материалов варианта вынесен
  в отдельные записи связи.
- **2НФ:** у четырёх основных сущностей ключ состоит из одного атрибута.
  Назначение и порядок показа материала задаются для полной пары
  `(variant_id, material_id)`, а не для материала или варианта в отдельности.
- **3НФ:** описание товара, характеристики оттенка и сведения о материале
  находятся в соответствующих сущностях. Вариант хранит их ключи, а запись
  связи не дублирует название или адрес материала.

`sku` уникален в каталоге. Пара `(variant_id, material_id)` также уникальна;
`display_order` — положительный номер, уникальный в пределах варианта.
Порядок показа задаётся для каждого варианта самостоятельно и не вычисляется
из вида материала. Компоненты RGB — целые числа от 0 до 255;
`net_weight_g` — положительная масса в граммах.

## Связь с операциями программы

Операция «Предоставить сведения о варианте» читает все пять сущностей:
вариант, товар, оттенок, записи связи и материалы. Операция «Подготовить
параметры наложения» получает RGB оттенка по `shade_id`; интенсивность поступает
от пользователя и не хранится как свойство товара. Операция «Предоставить
результат предварительного выбора» получает идентификатор варианта от
покупателя и возвращает его сведения. Автоматического выбора нет.

Изображение, контур и маска не входят в каталог. Они передаются функциям
обработки как временные данные.

## Ожидаемые результаты

| Действие | Ожидаемый результат |
|---|---|
| Получить сведения V001 | Товар P001; артикул DEMO-001; Розовый; 3,5 г; материалы M002, M001 |
| Переключить V001 на V002 | RGB меняется с (190, 90, 120) на (135, 45, 85); набор материалов сохраняется |
| Переключить V001 на V003 | RGB остаётся (190, 90, 120); масса меняется на 1,5 г; M002 заменяется на M003 |
| Выбрать V003 | Результат содержит V003, его артикул, товар, оттенок и массу |
| Запросить отсутствующий V999 | Сообщение об отсутствии варианта; наложение не запускается |

Одинаковые RGB и интенсивность для V001 и V003 должны давать одинаковый
результат наложения на одинаковые изображение и маску: масса упаковки
не влияет на цветовой алгоритм.
