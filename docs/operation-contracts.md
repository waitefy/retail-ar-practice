# Контракты операций

Основание: [описание бизнес-процесса](business-process.md)
и [демонстрационный каталог](catalog.md).
Данные каталога: [catalog.json](../src/data/catalog.json).

Документ задаёт контракты шести функций: параметры, результаты и условия отказа.
Названия операций совпадают с задачами BPMN и таблицей автоматизации.

## Общие правила данных и результата

Функции получают данные через параметры и не изменяют входные структуры.
Классы для сущностей и глобальное изменяемое состояние не используются.
Каталог — `dict` с пятью коллекциями записей из JSON. Перед вызовом операций
каталог должен пройти проверку состава записей, уникальности ключей,
внешних ключей и ограничений каталога. Ошибка загрузки сообщается до вызова
операций.

Каждая из шести функций возвращает обычный словарь:

- Успех: `{"ok": True, "data": результат, "error": None}`.
- Отказ: `{"ok": False, "data": None, "error": {"code": код, "message": пояснение}}`.

Изображение — непустой прямоугольный `list` строк. Пиксель — `list` из трёх
целых компонент RGB в диапазоне 0–255. Обращение к пикселю — `image[y][x]`.
Маска — прямоугольный `list` строк из `bool` той же высоты и ширины.

Контур — `list` вершин; вершина — `list` из двух координат `[x, y]`.
Координаты задаются относительно границ пикселей: центр пикселя `(x, y)`
находится в точке `(x + 0.5, y + 0.5)`. Допустимы конечные `int` и `float`,
кроме `bool`; границы координат — `0 <= x <= W` и `0 <= y <= H`.
Контур замыкается неявно: последнюю вершину соединяем с первой.

Цвет — `list` из трёх целых компонент RGB. Интенсивность — конечное число
`int` или `float`, кроме `bool`, от 0 до 1 включительно.

## Операции и сигнатуры

| Задача BPMN / операция | Функция | Вход | Успешный результат | Условия отказа |
|---|---|---|---|---|
| Предоставить сведения о варианте | get_variant_details(catalog, variant_id) | Проверенный каталог; непустой строковый идентификатор варианта | Связанные сведения о товаре, варианте, оттенке и материалах | Некорректный идентификатор; вариант не найден |
| Подготовить параметры наложения | prepare_overlay_parameters(catalog, variant_id, intensity) | Каталог; идентификатор варианта; интенсивность | Идентификатор варианта, RGB оттенка, интенсивность | Некорректный идентификатор; вариант не найден; некорректная интенсивность |
| Проверить данные визуализации | validate_visualization_input(image, contour, color, intensity) | Изображение, контур, RGB и интенсивность | Высота H, ширина W и число вершин K | Ошибочное изображение, цвет, интенсивность или контур |
| Построить маску области губ | build_lip_mask(height, width, contour) | H, W и контур, прошедшие предыдущую проверку | Новая булева маска H × W | Маска не содержит ни одного выбранного пикселя |
| Наложить выбранный оттенок | apply_shade(image, mask, color, intensity) | Проверенные изображение, цвет и интенсивность; маска предыдущей операции | Новое RGB-изображение тех же размеров | На корректных входах отказов нет |
| Предоставить результат предварительного выбора | get_selection_result(catalog, variant_id) | Каталог; идентификатор выбранного варианта либо None | Итог «выбран вариант» с его сведениями либо «без выбора» | Некорректный идентификатор; указанный вариант не найден |

`build_lip_mask` и `apply_shade` — вычислительные функции с проверенными
входами. Программа вызывает их только после успешной валидации; они не
повторяют полный обход изображения и проверку геометрии.

## Состав успешных результатов

### Предоставить сведения о варианте

`data` содержит `product`, `variant`, `shade` и `materials`.
Первые три поля — копии соответствующих записей каталога. `materials` —
список элементов с полями `material`, `display_role`, `display_order`,
упорядоченный по `display_order`. Поле `material` содержит копию записи
материала. Записи связи отбираются по `variant_id`, поэтому операция
использует все пять сущностей и разрешённую связь M:N.

Ссылки выдаются как метаданные, без сетевых запросов. Пустой набор материалов
не запрещает выдачу текстовых сведений о варианте. Доступность фотографий
по ссылкам не проверяется и не выдаётся за подтверждённую.

### Подготовить параметры наложения

`data` содержит `variant_id`, `color` и `intensity`.
Например, для V001 и интенсивности 0.5: `color = [190, 90, 120]`.
Для V003 при той же интенсивности параметры цвета совпадают.
Масса упаковки и фотографии не участвуют в расчёте цвета.

Для выбранной реализации необходимым материалом визуализации являются
параметры оттенка из каталога. Изображение сцены и контур поступают отдельно.
Обычный просмотр карточки не зависит от наличия изображения и контура.

### Проверить данные визуализации

Успех возвращает `{"height": H, "width": W, "vertex_count": K}`.
Проверки выполняются в фиксированном порядке: изображение, цвет,
интенсивность, контур. При отказе возвращается первая обнаруженная ошибка.

Изображение должно иметь хотя бы одну строку и один столбец; все строки
одинаковой длины, каждый пиксель содержит ровно три допустимых компоненты.
Контур должен иметь минимум три вершины, без повторяющихся вершин и
нулевых рёбер. Повтор первой вершины в конце считается ошибкой входа,
поскольку замыкание неявное. Проверяются структура и границы координат,
ненулевая площадь, отсутствие самопересечений и самокасаний.
Соседние рёбра могут иметь только свою общую вершину; наложение рёбер
не допускается. Порядок обхода по или против часовой стрелки допустим.

### Построить маску области губ

Для каждого центра пикселя проверяется принадлежность многоугольнику.
Центр на границе включается в маску. Для остальных центров применяется
правило нечётного числа пересечений горизонтального луча с рёбрами.
При подсчёте пересечений вершина ребра учитывается только один раз
с помощью полуоткрытого интервала по вертикали; горизонтальные рёбра
не добавляют пересечений. Проверка попадания на границу выполняется отдельно.

Ненулевая геометрическая площадь ещё не гарантирует, что область содержит
центр хотя бы одного пикселя. При пустой маске возвращается отказ
`empty_mask`: наложение не выполняется, требуется другой контур или кадр.

### Наложить выбранный оттенок

Для каждой компоненты выбранного маской пикселя вычисляется
`(1 - intensity) * original + intensity * color`.
Округление до целого — `floor(value + 0.5)`: половина округляется вверх.
Для пикселей вне маски компоненты копируются без изменений.
При интенсивности 0 возвращается точная копия исходного изображения;
при интенсивности 1 выбранные пиксели получают RGB оттенка.
Строки и пиксели результата создаются заново и не ссылаются на изменяемые
списки исходного изображения.

### Предоставить результат предварительного выбора

Для существующего варианта `data` содержит
`{"outcome": "selected", "selection": сведения_о_варианте}`.
Сведения имеют тот же состав, что у `get_variant_details`.
Для `variant_id = None` результат успешен:
`{"outcome": "no_selection", "selection": None}`.
Несуществующий идентификатор не трактуется как добровольный выход.

Вариант выбирает покупатель. Сортировка материалов регулирует их показ,
а не ранжирует варианты. Переход в магазин возможен по `product_url`, но
программа не открывает ссылку автоматически и не создаёт заказ.

## Коды отказа и реакция программы

| Код | Причина | Реакция вызывающей программы |
|---|---|---|
| invalid_variant_id | Идентификатор не является непустой строкой | Сообщить об ошибке ввода; не подменять вариант |
| variant_not_found | Идентификатор отсутствует в каталоге | Предложить существующие варианты; не выполнять наложение |
| invalid_intensity | Интенсивность не соответствует диапазону и типу | Предложить исправить значение; обычный просмотр доступен |
| invalid_image | Нет изображения либо нарушена структура или диапазон RGB | Сообщить об ошибке; не возвращать некорректные данные как готовый кадр |
| invalid_color | RGB для обработки не соответствует требованиям | Не выполнять наложение; сохранить обычный просмотр |
| missing_contour | Передан None или пустой список контура | Показать корректный исходный кадр без наложения; предложить повторить ввод |
| invalid_contour | Контур нарушает требования структуры или геометрии | Показать корректный исходный кадр без наложения; сообщить причину |
| empty_mask | Внутри корректного контура нет центров пикселей | Показать исходный кадр без наложения; предложить другой контур |

В деталях `invalid_contour` сообщение различает недостаток вершин,
выход за границы, повтор вершин, нулевую площадь и нарушения пересечений.
Поле `data` отказавшей функции остаётся `None`. Исходный кадр при отказе
визуализации предоставляет вызывающая программа из своих входных данных,
если он корректен. Во всех случаях входные структуры сохраняются.

## Последовательность вызовов и повторное сравнение

1. Загрузить и проверить каталог; предоставить сведения о выбранном для
   просмотра варианте. Открытие карточки остаётся началом процесса BPMN.
2. Если покупатель продолжает обычный просмотр, перейти к сравнению или
   предварительному выбору без вызова визуализации.
3. При запросе наложения подготовить параметры оттенка, проверить данные,
   построить маску и наложить оттенок. При первом отказе прекратить эту
   последовательность и сообщить причину.
4. При смене варианта получить его сведения и параметры. При неизменных
   изображении и контуре разрешено повторно использовать уже проверенную
   маску; новый цвет накладывается на исходное изображение, а не на результат
   предыдущего оттенка. Новый кадр или контур требует новой проверки и маски.
5. Получить итог по решению покупателя либо завершить без выбора. Временные
   данные обрабатываются в памяти; пользовательские снимки не записываются.

Контракты принимают готовые изображение и контур. В BPMN задано требование
прекратить использование камеры при завершении AR-просмотра, если она
используется внешним компонентом получения кадров.

## Алгоритмы и границы оценки сложности

Построение маски: `O(H * W * K)` по времени и `O(H * W)` по памяти.
Перебираются строки, пиксели и рёбра контура; проверка границы и ветвления
по пересечениям входят в эту оценку. Проверка пустоты маски не меняет порядок.
Наложение оттенка: `O(H * W)` по времени и `O(H * W)` по памяти результата,
включая копирование при нулевой интенсивности; три компоненты — константа.

Предварительная валидация требует `O(H * W + K²)` по времени: проверяются
пиксели и попарные отношения рёбер контура. Поэтому весь сценарий обработки
имеет оценку `O(H * W * K + K²)`, а не только стоимость построения маски.
В выдаче материалов отдельно учитывается сортировка `L` связей выбранного
варианта за `O(L log L)`; она не является одним из двух основных алгоритмов.

## Контрольный пример

Исходное изображение — 3 × 3 пикселя, каждый RGB `[100, 100, 100]`.
Контур: `[[0, 0], [2, 0], [2, 2], [0, 2]]`; интенсивность — 0.5.
Ожидаемая маска:

```text
True  True  False
True  True  False
False False False
```

Для V001 четыре выбранных пикселя получают `[145, 95, 110]`.
Для V002 — `[118, 73, 93]`, с указанным округлением половины вверх.
Для V003 результат совпадает с V001. Пять остальных пикселей и весь
исходный массив не меняются. При интенсивности 0 все девять пикселей
результата равны исходным.

Дополнительные проверки: отсутствие контура, самопересечение,
вершина за границей изображения, пустая маска для малого многоугольника,
центр пикселя на границе, отсутствующий V999, выход с None и повторное
наложение после смены оттенка. Эти сценарии дополняют требования контрактов.
