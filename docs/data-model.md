# Логическая модель данных каталога

Основание: [описание процесса](business-process.md),
[BPMN и таблица операций](process-model.md),
[демонстрационный каталог](catalog.md).
Модель соответствует полям [catalog.json](../src/data/catalog.json).

[Редактируемая ER-диаграмма](../models/er_logical.drawio) •
[Изображение диаграммы](../models/er_logical.png).

Используется нотация Crow’s Foot. Указаны сущности, атрибуты, первичные
и внешние ключи, обязательность и кратности связей. Модель не привязана
к СУБД. Списки JSON служат представлением записей связанных сущностей.

## Сущности и назначение

| Сущность / коллекция | Назначение в процессе | Атрибуты | Первичный ключ | Внешние ключи |
|---|---|---|---|---|
| Товар / products | Название, описание и внешняя страница товара для обычного просмотра | product_id, name, description, product_url | product_id | — |
| Вариант товара / variants | Конкретное исполнение, которое покупатель просматривает и выбирает | variant_id, product_id, shade_id, sku, net_weight_g | variant_id | product_id → products.product_id; shade_id → shades.shade_id |
| Оттенок / shades | Название и RGB, общие для вариантов с одинаковым оттенком | shade_id, name, red, green, blue | shade_id | — |
| Материал / materials | Метаданные фотографии или палитры карточки товара | material_id, kind, title, url | material_id | — |
| Материал варианта / variant_materials | Принадлежность материала варианту, назначение и порядок показа | variant_id, material_id, display_role, display_order | (variant_id, material_id) | variant_id → variants.variant_id; material_id → materials.material_id |

Все пять сущностей входят в каталог — хранилище данных основной BPMN
исходного процесса. На ней также показаны сведения о товаре, варианте и оттенке,
фотографии и палитра, результат предварительного выбора.
Операция «Предоставить сведения о варианте» использует их для формирования
карточки: находит вариант, товар и оттенок, затем связи и материалы.
Состав результата задан контрактом `get_variant_details`
в [описании операций](operation-contracts.md).
Оттенок также задаёт RGB для обработки изображения. Фотографии и палитра
помогают обычному просмотру, который доступен независимо от визуализации.

Кадр, контур и маска являются временными входами и результатами вычислений.
Они не образуют дополнительные сущности постоянного каталога.

## Атрибуты и ограничения

| Атрибут | Смысл и допустимые значения |
|---|---|
| product_id, variant_id, shade_id, material_id | Непустые строковые идентификаторы; PK уникален в своей сущности, FK обязательно находит родителя |
| products.name | Непустое название товара |
| products.description | Непустое описание товара |
| products.product_url | Абсолютный адрес страницы товара с протоколом HTTP или HTTPS |
| variants.sku | Непустой артикул; уникален во всём каталоге |
| variants.net_weight_g | Конечная положительная масса нетто в граммах |
| shades.name | Непустое название оттенка |
| shades.red, shades.green, shades.blue | Три отдельных целых значения от 0 до 255 |
| materials.kind | Непустое обозначение вида материала; в примере photo и palette |
| materials.title | Непустое название материала |
| materials.url | Абсолютный адрес материала с протоколом HTTP или HTTPS |
| variant_materials.display_role | Непустое обозначение назначения материала в карточке; в примере packaging и shade_comparison |
| variant_materials.display_order | Положительный целый номер; пара (variant_id, display_order) уникальна |

Значения `bool` не принимаются как числовые атрибуты. Пустые строки,
в том числе состоящие только из пробелов, недопустимы. Название оттенка
и адрес материала не объявляются уникальными: такое ограничение
не следует из процесса. Вид материала не определяет его роль и порядок
в конкретной карточке — их задаёт запись связи.

Представление каталога в JSON содержит ровно пять коллекций и перечисленные
поля записей; к ним применяются указанные ограничения ключей и значений.
Пустой каталог допустим; обращение к неизвестному варианту по контракту
возвращает отказ. Ограничения адресов касаются структуры и протокола;
доступность файлов по этим адресам моделью не подтверждается.

## Связи

| Родитель → дочерняя сущность | Кратность | Смысл |
|---|---|---|
| Товар → Вариант товара | 1 → 0..N | У товара может быть несколько вариантов; каждый вариант принадлежит ровно одному товару |
| Оттенок → Вариант товара | 1 → 0..N | Один оттенок может использоваться в нескольких вариантах; каждый вариант имеет ровно один оттенок |
| Вариант товара → Материал варианта | 1 → 0..N | У варианта может быть несколько связей с материалами; каждая связь относится ровно к одному варианту |
| Материал → Материал варианта | 1 → 0..N | Один материал может входить в карточки нескольких вариантов; каждая связь указывает ровно один материал |

Нижняя граница 0 допускает подготовленные записи, ещё не включённые
в карточки. Материалы необязательны: без них операция возвращает текстовые
сведения и пустой список `materials`. На стороне внешних ключей связь
обязательна: вариант без существующего товара или оттенка недопустим;
запись связи без варианта или материала также недопустима.

## Почему нужна связь M:N

Связь «Вариант товара — Материал» имеет кратность M:N и разрешена
ассоциативной сущностью «Материал варианта». В примере у каждого варианта
два материала. Палитра M001 используется у V001, V002 и V003, а фотография
полноразмерной упаковки M002 — у V001 и V002. M002 не содержит обозначения
оттенка, поэтому подходит обоим вариантам.

Это позволяет изменить адрес общей палитры одной правкой записи M001.
Копировать её название и URL в каждый вариант не требуется. Составной PK
запрещает повторно присоединять тот же материал к тому же варианту.
Альтернативный ключ `(variant_id, display_order)` запрещает два материала
на одной позиции карточки. Роль и позиция задаются для пары «вариант — материал».

## Обоснование нормализации

**1НФ.** Каждая запись имеет ключ, а каждый атрибут содержит одно значение.
Компоненты RGB разделены на три атрибута. Несколько материалов варианта
представлены отдельными записями связи, а не списком идентификаторов в поле варианта.

**2НФ.** В основных сущностях ключи простые. В ассоциативной сущности
`display_role` и `display_order` зависят от полной пары
`(variant_id, material_id)`: один материал может иметь разные роли и позиции
у разных вариантов. Для альтернативного ключа `(variant_id, display_order)`
материал и роль также определяются полной парой.

**3НФ.** Неключевые сведения находятся у своего объекта: название и описание
товара определяются `product_id`, параметры оттенка — `shade_id`, сведения
материала — `material_id`. Вариант и запись связи хранят ссылки; транзитивного
хранения этих названий, RGB или URL в них нет. Уникальный артикул определяет
тот же вариант и является его альтернативным ключом.

Например, без сущности «Оттенок» RGB `[190, 90, 120]` и название «Розовый»
повторялись бы у V001 и V003. После выделения оттенка оба варианта ссылаются
на одну запись S001. Изменение параметров S001 не создаёт расхождения между
полноразмерной и мини-версией.
