# Каталог и наложение оттенка

Язык — Python; проверенная версия — **3.14.7**. Используется только
стандартная библиотека, установка пакетов не требуется. Программа состоит
из функций и стандартных структур данных, собственных классов нет.

Реализована операция BPMN «Предоставить сведения о варианте»:
`get_variant_details(catalog, variant_id)` возвращает товар, вариант,
оттенок и связанные материалы в порядке показа. Структура каталога
соответствует [логической модели](../models/er_logical.drawio).

Вычислительная часть операции «Представить внешний вид варианта»:
`validate_visualization_input` проверяет входы, `build_lip_mask` строит маску,
`apply_shade` смешивает RGB внутри неё. Изображение и контур передаются
в JSON; камера и распознавание лица не подключаются.

[catalog.py](catalog.py) работает с [каталогом](data/catalog.json),
[geometry.py](geometry.py) проверяет геометрию,
[visualization.py](visualization.py) строит маску и накладывает оттенок.
[results.py](results.py) задаёт общий формат результата.

## Каталог

Из корня репозитория:

```bash
python --version
python src/catalog.py --variant V001
```

Вывод — JSON с полями `ok`, `data`, `error`. Для V001 ожидаются товар P001,
артикул DEMO-001, оттенок S001 «Розовый» с RGB (190, 90, 120) и материалы
M002, M001 в указанном порядке. `data` содержит `product`, `variant`,
`shade`, `materials`; каждый материал включает свою роль и порядок показа.
Каталог учебный: товар вымышленный, ссылки на retail-ar.example служат
обозначениями страницы и материалов. Сетевых запросов нет.

По умолчанию выбирается V001. Путь к каталогу определяется относительно
`catalog.py`, поэтому запуск возможен из другого рабочего каталога.
Свой файл задаётся параметром `--catalog`:

```bash
python src/catalog.py --catalog src/data/catalog.json --variant V003
```

Перед выдачей сведений проверяются пять коллекций, состав полей, значения,
уникальность ключей и артикулов, внешние ключи и порядок материалов.
Входные данные не изменяются, результат содержит копии записей.
Успех — код завершения `0`. Ошибки выводятся в `stderr`, код — `1`:
`catalog_read_error` — файл не прочитан; `invalid_catalog` — неверные данные;
`invalid_variant_id` — пустой идентификатор; `variant_not_found` — вариант
отсутствует. Например, `--variant V999` возвращает последнюю ошибку.
Неверные аргументы командной строки обрабатывает `argparse`, код — `2`.

## Наложение оттенка

```bash
python src/overlay_demo.py
```

[overlay_demo.py](overlay_demo.py) получает RGB варианта V001 из каталога
и читает [mask_example.json](data/mask_example.json): изображение 3 × 3
с RGB (100, 100, 100), контур `[[0,0],[2,0],[2,2],[0,2]]`, интенсивность `0.5`.
Ожидаемый вывод:

```text
Вариант: V001 / DEMO-001 / Розовый
Изображение: 3 × 3; вершин контура: 4
Маска:
1 1 0
1 1 0
0 0 0
Результат наложения (RGB):
[145, 95, 110] [145, 95, 110] [100, 100, 100]
[145, 95, 110] [145, 95, 110] [100, 100, 100]
[100, 100, 100] [100, 100, 100] [100, 100, 100]
```

Другой вариант и входной файл задаются через `--variant` и `--input`;
для каталога есть `--catalog`. Пути по умолчанию определяются относительно
скрипта. Например, `python src/overlay_demo.py --variant V002` даёт
RGB (118, 73, 93) внутри той же маски.

Контур должен быть простым многоугольником без повторяющихся вершин,
с конечными координатами внутри изображения; последнюю вершину повторять
не нужно. Пиксель входит в маску, если его центр лежит внутри контура
или на границе. Пустая маска возвращает ошибку `empty_mask`.
RGB содержит три целых числа от 0 до 255, интенсивность лежит в [0, 1].
Смешивание: `(1 − intensity) * исходный RGB + intensity * выбранный RGB`,
каждая компонента округляется до целого, половины вверх.
Интенсивность преобразуется из её десятичной записи в точную дробь,
чтобы погрешность `float` не меняла результат округления.
При интенсивности 0 изображение сохраняется, при 1 внутри маски получается
выбранный цвет. Пиксели снаружи сохраняются; результат содержит новые списки.
Для сравнения оттенков каждый вызов получает исходное изображение.

Ошибки чтения и проверки входов: `invalid_input`, `invalid_image`, `invalid_color`,
`invalid_intensity`, `missing_contour`, `invalid_contour`, `empty_mask`.
Диагностика идёт в `stderr`, код завершения 1; успешный запуск возвращает 0.
Алгоритмы принимают проверенные входы; маску для `apply_shade` создаёт
`build_lip_mask`. Проверки геометрии выполняются перед этими вызовами.

## Проверка

```bash
python -m py_compile src/results.py src/catalog.py src/catalog_checks.py src/geometry.py src/visualization.py src/overlay_demo.py src/checks.py
python src/checks.py
```

Ожидаемый итог: `Пройдено групп проверок: 20`. [checks.py](checks.py)
вызывает проверки каталога из [catalog_checks.py](catalog_checks.py)
и проверяет геометрию, маску, смешивание, округление, неизменность входов
и консольные запуски из другого каталога. Запускать без `-O`, который
отключает `assert`.
