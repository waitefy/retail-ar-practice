# Просмотр и предварительный выбор варианта на Java

Программа показывает сведения о варианте, накладывает его оттенок на
изображение по контуру губ и возвращает результат предварительного выбора.
Данные соответствуют [логической модели](../../models/er_logical.drawio),
классы — [UML-диаграмме](../../models/classes.drawio).

Пять сущностей представлены неизменяемыми классами `record`: их поля закрыты,
доступны методы чтения. `Catalog` хранит коллекции и выполняет операцию,
`CatalogLoader` читает JSON и проверяет ограничения. Список материалов в
результате также неизменяем. Сетевых запросов при запуске программы нет.

`Main` запускает `VariantLookup` или `ShadePreview` через интерфейс
`VariantOperation`. Общий класс `CatalogOperation` получает сведения о варианте.
`VariantLookup` возвращает эти сведения. `ShadePreview` строит маску, накладывает
оттенок и формирует результат выбора по флагу `--select`.

`Polygon` проверяет геометрию контура и определяет принадлежность точки области.
`LipMaskBuilder` хранит размеры и проверенный контур, строит новую маску при каждом
вызове. Эти классы проверяются на том же примере, что и Python-версия.

## Среда и сборка

Проверено с **OpenJDK 27.0.1.0.3**, `javac 27.0.1.0.3`, на Linux.
Инструмент сборки — `javac`. Единственная зависимость — **Gson 2.11.0**
([проект библиотеки](https://github.com/google/gson)).

Команды выполняются **из корня репозитория**. При первой сборке скачать JAR
из Maven Central; он хранится локально и не включается в Git:

```bash
java -version
javac -version
mkdir -p src/java/lib src/java/out
curl --fail --location https://repo.maven.apache.org/maven2/com/google/code/gson/gson/2.11.0/gson-2.11.0.jar -o src/java/lib/gson-2.11.0.jar
echo '57928d6e5a6edeb2abd3770a8f95ba44dce45f3b23b7a9dc2b309c581552a78b  src/java/lib/gson-2.11.0.jar' | sha256sum -c -
javac -encoding UTF-8 -Xlint:all -cp src/java/lib/gson-2.11.0.jar -d src/java/out src/java/retailar/*.java
```

Для сборки нужен доступ к Maven Central либо локальный JAR указанной версии
с тем же SHA-256. После получения зависимости сборка и запуск работают без сети.
В Windows разделитель элементов classpath — `;` вместо `:`.

## Запуск и результат

```bash
java -cp 'src/java/out:src/java/lib/gson-2.11.0.jar' retailar.Main --variant V001
```

По умолчанию читается `src/data/catalog.json` относительно текущего каталога,
выбирается V001. Путь можно задать явно, в том числе абсолютный:

```bash
java -cp 'src/java/out:src/java/lib/gson-2.11.0.jar' retailar.Main --catalog src/data/catalog.json --variant V003
```

Вход — JSON с пятью коллекциями: `products`, `variants`, `shades`, `materials`,
`variant_materials`. Используется один [учебный каталог](../data/catalog.json),
общий с Python-версией. Проверяются поля, значения, PK/FK, уникальность SKU,
составного ключа связи и порядка материалов. Повторные ключи JSON,
NaN/Infinity, дробные RGB и логические значения вместо чисел отклоняются.
Материалы варианта необязательны; пустой каталог допустим.

Вывод — JSON вида `{"ok": true, "data": {...}, "error": null}`. В `data`:

| Вариант | Товар | Оттенок | Масса, г | Материалы по порядку |
| --- | --- | --- | --- | --- |
| V001 | P001 | S001, RGB [190, 90, 120] | 3.5 | M002, M001 |
| V002 | P001 | S002, RGB [135, 45, 85] | 3.5 | M002, M001 |
| V003 | P001 | S001, RGB [190, 90, 120] | 1.5 | M003, M001 |

`data.product`, `data.variant` и `data.shade` содержат полные записи.
Каждый элемент `data.materials` содержит `material` с полной записью,
`display_role` и `display_order`. Названия полей и значения совпадают с выводом:

```bash
python src/catalog.py --variant V001
```

Успех — код завершения `0`. При ошибке выводится сообщение в `stderr`,
`stdout` пуст, код — `1`: `catalog_read_error` (файл недоступен),
`invalid_catalog` (неверные данные), `invalid_variant_id` (пустой идентификатор),
`variant_not_found` (вариант отсутствует). Например:

```bash
java -cp 'src/java/out:src/java/lib/gson-2.11.0.jar' retailar.Main --variant V999
```

Результат: `Ошибка [variant_not_found]: Вариант V999 отсутствует в каталоге.`
Неверные аргументы командной строки дают код `2`; `--help` — справку и код `0`.

Если данные лежат внутри самостоятельной копии Java-проекта в
`src/java/data/catalog.json`, запускать с `--catalog src/java/data/catalog.json`.
Компиляция от Python и расположения файла данных не зависит.

## Наложение оттенка и предварительный выбор

```bash
java -cp 'src/java/out:src/java/lib/gson-2.11.0.jar' retailar.Main --variant V002 --input src/data/mask_example.json
```

Входной [пример](../data/mask_example.json) содержит `image` (прямоугольную
матрицу целочисленных RGB от 0 до 255), `contour` (вершины `[x, y]`) и
`intensity` (конечное число от 0 до 1). Цвет берётся из каталога. Для отдельной
копии проекта с обоими JSON в `src/java/data` укажите
`--catalog src/java/data/catalog.json --input src/java/data/mask_example.json`.

С `--input` в `data` возвращаются `details` (сведения о варианте),
`mask` (матрица логических значений), `image` (новая матрица RGB)
и `selection` (результат предварительного выбора).
В примере маска включает левый верхний квадрат 2 × 2. В нём получаются
`[118, 73, 93]` для V002 и `[145, 95, 110]` для V001 и V003.
Остальные пиксели имеют исходное значение `[100, 100, 100]`.

В приведённой команде просмотр завершается с
`"selection": {"status": "no_selection", "details": null}`.
Оба результата выбора возвращаются с кодом завершения `0`. Добавьте
`--select`, чтобы получить статус `selected` и сведения об открытом
варианте в `selection.details`.

```bash
java -cp 'src/java/out:src/java/lib/gson-2.11.0.jar' retailar.Main --variant V002 --input src/data/mask_example.json --select
```

При запуске с `--select` без `--input` изображение читается из
`src/data/mask_example.json`.
Без `--input` и `--select` запускается просмотр сведений из каталога.

Внутри маски каждая компонента вычисляется как
`(1 - intensity) * original + intensity * shade`. Смешивание выполняется
в `BigDecimal`, половины округляются вверх. Исходное изображение
сохраняется. Наложение требует `O(H·W)` арифметических операций и `O(H·W)`
памяти для результата. Ошибки входного файла, изображения и интенсивности
возвращают код завершения `1` и диагностику `invalid_input`, `invalid_image`
или `invalid_intensity` соответственно. Ошибки контура и маски описаны ниже.

## Построение маски

API принимает положительные размеры изображения `height`, `width` и список
вершин `[x, y]`. Например, после импорта `java.util.List` и `retailar.LipMaskBuilder`:

```java
var builder = new LipMaskBuilder(3, 3,
        List.of(List.of(0, 0), List.of(2, 0), List.of(2, 2), List.of(0, 2)));
boolean[][] mask = builder.build();
```

Это контур из общего [mask_example.json](../data/mask_example.json). Результат
(`1` — `true`, `0` — `false`):

```text
1 1 0
1 1 0
0 0 0
```

Контур содержит не менее трёх вершин внутри изображения; замыкание неявное.
Проверяются конечность координат, повторные вершины, ненулевая площадь,
самопересечения, самокасания и наложение соседних рёбер. Коллинеарные соседние
рёбра без наложения допустимы. Центр пикселя — `(x + 0.5, y + 0.5)`;
граница области включается. Направление обхода и начальная вершина не влияют
на результат.

Целые координаты сохраняются точно. Дробные координаты интерпретируются как
`double`, затем `new BigDecimal(double)` сохраняет их точное двоичное значение,
как `Fraction(float)` в Python. Геометрические операции выполняются без
округления и без допуска epsilon. Входной контур копируется; строки маски
и результаты разных вызовов независимы.

`VisualizationException` содержит код и сообщение: `invalid_image`
(неположительные размеры), `missing_contour` (нет вершин), `invalid_contour`
(неверный контур), `empty_mask` (в области нет центров пикселей).

Проверка контура требует `O(K²)` арифметических операций, проверка одной точки —
`O(K)`, построение маски — `O(H·W·K)`. Память маски — `O(H·W)`, проверенного
контура — `O(K)`. Здесь `K` — число вершин, `H`, `W` — размеры изображения;
стоимость операций `BigDecimal` зависит от разрядности чисел.

## Проверки

Из корня репозитория, после получения Gson:

```bash
javac -encoding UTF-8 -Xlint:all -cp src/java/lib/gson-2.11.0.jar -d src/java/out src/java/retailar/*.java src/java/tests/retailar/*.java
java -cp 'src/java/out:src/java/lib/gson-2.11.0.jar' retailar.CatalogChecks src/data/catalog.json
java -cp 'src/java/out:src/java/lib/gson-2.11.0.jar' retailar.MaskChecks src/data/mask_example.json
java -cp 'src/java/out:src/java/lib/gson-2.11.0.jar' retailar.PreviewChecks src/data/catalog.json src/data/mask_example.json
```

Семь групп проверяют сведения и порядок материалов, структуру коллекций,
ключи и связи, значения, чтение JSON, неизменяемость результатов и CLI.
Последняя строка: `Пройдено групп проверок каталога: 7`.
Для самостоятельной копии с данными внутри Java-проекта в команде проверок
указываются `src/java/data/catalog.json` и `src/java/data/mask_example.json`.

Восемь групп проверок маски охватывают общий пример, ошибки контура,
самопересечения и наложения, порядок вершин, границу области, вогнутые контуры,
пустые и тонкие области, защиту исходных данных. Последняя строка:
`Пройдено групп проверок маски: 8`.

Пять групп проверок просмотра охватывают полный CLI-вывод для трёх
вариантов, округление, интенсивности 0 и 1, независимость входов и результатов,
диагностику неверных входов и оба результата выбора. Последняя строка
проверок — `Пройдено групп проверок просмотра оттенка и выбора: 5`.
